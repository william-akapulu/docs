You create the Daily room. The live-session call starts the Akapulu Labs worker. Your voice bot's job is to send the assistant audio to that worker. The worker joins the call as a Daily participant and publishes the audio and the video. The voice bot does not publish audio or video.

For LiveKit Agents, see [LiveKit](/guides/calls/livekit).

## 1. Create the room

`create_akapulu_call`, from [`pipecat-akapulu`](https://github.com/Akapulu/pipecat-akapulu), runs on your server, before the voice bot starts. It reads `DAILY_API_KEY` and `AKAPULU_API_KEY`. It creates a private Daily room for three participants: the user browser, your voice bot, and the Akapulu Labs worker. It mints the three meeting tokens and `POST /api/live-sessions/` (Daily transport). It returns the room URL, the bot token, the browser token, and `session_id`. The worker token is sent to Akapulu Labs and is not returned.

The room lasts two hours unless you pass `room_exp_secs`. Daily removes everyone when the room expires. The browser joins as `You`. The worker joins as `Avatar`. Daily Prebuilt shows the browser and the avatar.

```python
from pipecat_akapulu import create_akapulu_call

room_url, bot_token, browser_token, session_id = await create_akapulu_call(
    avatar_id="<avatar uuid>",
    show_ai_label=True,
    session=session,
)
```

`session` is an `aiohttp.ClientSession`. The voice bot joins Daily with `bot_token`. The browser joins with `browser_token`. Pass `session_id` to `AkapuluAvatar`.

A bot that already has a Daily room skips `create_akapulu_call`. Mint the Akapulu Labs worker's meeting token and `POST /api/live-sessions/` yourself.

## 2. Start the live session

This is the call `create_akapulu_call` makes. Use it yourself when the Daily room already exists. Put the Akapulu Labs worker's meeting token in `avatar_token`. Your voice bot joins Daily with its token. The browser joins Daily with its token.

```bash
curl -X POST "{{api-base-url}}/live-sessions/" \
  -H "Authorization: Bearer $AKAPULU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "avatar_id": "<avatar uuid>",
    "show_ai_label": true,
    "room_url": "https://<your-domain>.daily.co/<room>",
    "avatar_token": "<avatar meeting token>"
  }'
```

Omit `transport` or set `"transport": "daily"`. `show_ai_label` is a boolean. On success the response is:

```json
{
  "session_id": "11111111-2222-3333-4444-555555555555"
}
```

The call returns when the session is stored and the Akapulu Labs worker has been asked to start. It does not wait for the first video frame.

Field rules are on [Create a live session](/api-reference/live-sessions/create).

## Loading status

The `AkapuluAvatar` Pipecat plugin connects to the Akapulu Labs worker in the background. When the pipeline starts, it forwards `StartFrame` right away so your voice bot keeps moving. It does not wait for the first face frame.

While the Akapulu Labs worker boots, the plugin pushes **RTVI server messages** into your voice-bot pipeline. Each message body has `type` `status` and these fields:

- `call_is_ready`: whether this tap has decoded enough Avatar video frames (not the GPU first-publish stamp)
- `completion_percent`: how far startup has gotten (0 to 100)
- `latest_update_text`: the latest human-readable startup line

Those are not Daily audio or video tracks. With RTVI on the call (for example `@pipecat-ai/client-js` in the browser), they arrive on the client as RTVI `ServerMessage` events over that same Daily connection. Use them for a loading spinner, percent, and copy. Keep the loading UI up until `call_is_ready` is true. When that gate opens the tap also sends `{"type":"call_ready"}` on the private audio socket so the worker can stamp Django `call_is_ready_at`.

## 3. Put AkapuluAvatar in the pipeline

Install [`pipecat-akapulu`](https://github.com/Akapulu/pipecat-akapulu) (`pipecat-akapulu==0.1.22`). Put the `AkapuluAvatar` Pipecat plugin after your TTS (or whatever produces assistant audio). `AkapuluAvatar` sends that audio to the Akapulu Labs worker. The worker joins the call as a Daily participant and publishes the audio and the video. Use `akapulu_daily_params()` so the voice bot does not publish audio or video. Call `avatar.attach(transport)` so the package unsubscribes this bot from the Avatar microphone and captures Avatar video for `call_is_ready`. Await `wait_until_call_ready` before greeting. The browser stays subscribed to the Avatar microphone.

```python
from pipecat.pipeline.pipeline import Pipeline
from pipecat.transports.daily.transport import DailyTransport
from pipecat_akapulu import AkapuluAvatar, akapulu_daily_params

transport = DailyTransport(
    room_url,
    bot_token,
    bot_name,
    akapulu_daily_params(),
)

stt = YourVoiceBotSTT()
llm = YourVoiceBotLLM()
tts = YourVoiceBotTTS()
avatar = AkapuluAvatar(session_id=session_id)
avatar.attach(transport)

pipeline = Pipeline(
    [
        transport.input(),
        stt,
        llm,
        tts,
        avatar,
        transport.output(),
    ]
)

await avatar.wait_until_call_ready()
```

`YourVoiceBotSTT`, `YourVoiceBotLLM`, and `YourVoiceBotTTS` are stand-ins for your own STT, LLM, and TTS.

The avatar worker needs about 800 ms of assistant audio before it starts rendering the video. The render itself, given the audio, only takes around 150ms. You might see added latency in your bot's response even if your TTS provider's TTFA is low, due to this buffer accumulation. A TTS that trickles audio in slowly fills that buffer late, so the response is slower and the avatar gestures less. We recommend a TTS that sends audio in waves. Cartesia has been the best in our testing.

The public example is [akapulu-examples](https://github.com/Akapulu/akapulu-examples): a local server, a page, and a voice bot that speaks first.

## Errors

When `POST /api/live-sessions/` fails, the response JSON includes `error` and `error_code`. Branch on `error_code`. The codes are in the [API overview](/api-reference/introduction#error-responses).
