You create the room. The live-session call starts the Akapulu Labs worker. Your voice bot's job is to send the assistant audio to that worker. The worker joins the call as a Daily participant and publishes the audio and the video. The voice bot does not publish audio or video.

## 1. Create the room

Create a private Daily room for three participants: the user browser, your voice bot, and the Akapulu Labs worker. Mint three meeting tokens, one for each participant.

When you `POST /api/live-sessions/`, put the Akapulu Labs worker's meeting token in `avatar_token`. Your voice bot joins Daily with its token. The browser joins Daily with its token.

## 2. Start the live session

```bash
curl -X POST "{{api-base-url}}/live-sessions/" \
  -H "Authorization: Bearer $AKAPULU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "avatar_id": "<avatar uuid>",
    "show_ai_label": true,
    "room_url": "https://<your-domain>.daily.co/<room>",
    "avatar_token": "<avatar meeting token>"
  }'
```

`show_ai_label` is a boolean. On success the response is:

```json
{
  "session_id": "11111111-2222-3333-4444-555555555555"
}
```

The call returns when the session is stored and the Akapulu Labs worker has been asked to start. It does not wait for the first video frame.

## Loading status

The `AkapuluAvatar` Pipecat plugin connects to the Akapulu Labs worker in the background. When the pipeline starts, it forwards `StartFrame` right away so your voice bot keeps moving. It does not wait for the first face frame.

While the Akapulu Labs worker boots, the plugin pushes **RTVI server messages** into your voice-bot pipeline. Each message body has `type` `status` and these fields:

- `call_is_ready`: whether the Akapulu Labs worker has published the first frame
- `completion_percent`: how far startup has gotten (0 to 100)
- `latest_update_text`: the latest human-readable startup line

Those are not Daily audio or video tracks. With RTVI on the call (for example `@pipecat-ai/client-js` in the browser), they arrive on the client as RTVI `ServerMessage` events over that same Daily connection. Use them for a loading spinner, percent, and copy. Keep the loading UI up until `call_is_ready` is true.

## 3. Put AkapuluAvatar in the pipeline

Install [`pipecat-akapulu`](https://github.com/Akapulu/pipecat-akapulu). Put the `AkapuluAvatar` Pipecat plugin after your TTS (or whatever produces assistant audio). `AkapuluAvatar` sends that audio to the Akapulu Labs worker. The worker joins the call as a Daily participant and publishes the audio and the video. The voice bot does not publish audio or video, so `audio_out_enabled` and `video_out_enabled` stay `False`.

```python
from pipecat.pipeline.pipeline import Pipeline
from pipecat.transports.daily.transport import DailyParams, DailyTransport
from pipecat_akapulu import AkapuluAvatar

transport = DailyTransport(
    room_url,
    bot_token,
    bot_name,
    DailyParams(
        audio_in_enabled=True,
        audio_out_enabled=False,
        video_out_enabled=False,
    ),
)

stt = YourVoiceBotSTT()
llm = YourVoiceBotLLM()
tts = YourVoiceBotTTS()
avatar = AkapuluAvatar(session_id=session_id)

pipeline = Pipeline(
    [
        transport.input(),
        stt,
        llm,
        tts,
        avatar,
        transport.output(),
    ]
)
```

Assistant audio is resampled to 24000 Hz mono before it is sent. A frame that is already 24000 Hz mono is sent unchanged. The worker always receives 24000. The pipeline audio-out rate does not have to be a multiple of 25.

`YourVoiceBotSTT`, `YourVoiceBotLLM`, and `YourVoiceBotTTS` are stand-ins for your own STT, LLM, and TTS. Leave `audio_out_enabled` and `video_out_enabled` as `False` because the voice bot's job is to send the assistant audio to the Akapulu Labs worker. The worker joins the call as a Daily participant and publishes the audio and the video. The voice bot does not publish audio or video.

Pipecat subscribes your voice bot to every remote microphone. When the participant named `Avatar` joins, turn that microphone off. The voice bot still hears the browser. The browser stays subscribed to the Avatar microphone. That track is the voice the visitor hears.

```python
@transport.event_handler("on_participant_joined")
async def on_participant_joined(_transport, participant):
    info = participant.get("info")
    if not isinstance(info, dict):
        raise RuntimeError("Daily participant has no info")
    name = info.get("userName")
    if not isinstance(name, str) or not name:
        raise RuntimeError("Daily participant has no userName")
    if name != "Avatar":
        return
    participant_id = participant.get("id")
    if not isinstance(participant_id, str) or not participant_id:
        raise RuntimeError("Daily participant has no id")
    error = await transport.update_subscriptions(
        participant_settings={
            participant_id: {"media": {"microphone": "unsubscribed"}},
        },
    )
    if error:
        raise RuntimeError(f"Daily avatar microphone unsubscribe failed: {error}")
```

Call this once, when Avatar joins. Do not set subscriptions again on a participant update.

The public example is [akapulu-examples](https://github.com/Akapulu/akapulu-examples): a local server, a page, and a voice bot that speaks first.

## Errors

When `POST /api/live-sessions/` fails, the response JSON includes `error` and `error_code`. Branch on `error_code`. The codes are in the [API overview](/api-reference/introduction#error-responses).
