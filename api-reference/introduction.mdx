The API starts an avatar in a Daily room you create, and it reads the mark on a recording.

A browser UI is your page plus your Pipecat bot. The API key stays on your server. See [Your bot](/guides/calls/your-bot).

## Authentication

```bash
Authorization: Bearer <YOUR_AKAPULU_API_KEY>
```

Create a key from the dashboard after you sign in: [API keys]({{app-url}}/settings/api-keys/).

## Base URL

```bash
{{api-base-url}}
```

## Live session

```bash
curl -X POST "{{api-base-url}}/api/live-sessions/" \
  -H "Authorization: Bearer <YOUR_AKAPULU_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "avatar_id": "<avatar uuid>",
    "show_ai_label": true,
    "room_url": "https://<your-domain>.daily.co/<room>",
    "avatar_token": "<avatar meeting token>"
  }'
```

The response is `{"session_id": "<uuid>"}`. Field rules are on [Create a live session](/api-reference/live-sessions/create).

## Error responses

Failed calls return JSON with `error` and `error_code`. Branch on `error_code`.

| `error_code` | Typical status | When |
| --- | --- | --- |
| `AUTH_MISSING` | 401 | No Bearer API key |
| `AUTH_INVALID` | 401 | API key not recognized |
| `VALIDATION` | 400 | Missing or invalid fields |
| `AVATAR_NOT_FOUND` | 404 | `avatar_id` is not an avatar you can use |
| `NOT_FOUND` | 404 | Video-mark check is missing, or the mp4 was not uploaded |
| `ALREADY_READ` | 409 | That video-mark check was already read |
| `QUOTA_EXCEEDED` | 403 | No minutes remaining |
| `CONCURRENCY_LIMIT` | 403 | Too many concurrent calls for the plan |
| `INTERNAL` | 500 | The server could not finish the call |
