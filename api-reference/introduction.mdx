The Akapulu Labs API is the programmatic interface for building with Akapulu Labs: live conversations, scenarios, and scripted video clips.

<Note>
For a browser conversation UI, use the [Akapulu Labs Web SDK](/web-sdk/overview) instead of calling connect and updates from frontend code. Put the API key on **your server**, have the browser call **your** connect route, and authenticate users on that route before starting a call. The SDK's client and server libraries implement that flow, session state, realtime media wiring, and conversation detail and recording retrieval.

Scripted clips have no Web SDK. Call the [clip](/guides/clips/overview) and [take](/api-reference/takes/create) REST endpoints, or start from the [Python example](/examples/clips/scripted-clip-workflow).
</Note>

## Authentication

All Akapulu Labs API endpoints require a Bearer API key in the `Authorization` header.

```bash
Authorization: Bearer <YOUR_AKAPULU_API_KEY>
```

## API Keys

To get started, create an account, sign in to Akapulu Labs, then create an [API key](https://akapulu.com/api-keys/) and send it in the `Authorization` header for every request.

## Example Request

```bash
curl -X POST "https://akapulu.com/api/conversations/connect/" \
  -H "Authorization: Bearer <YOUR_AKAPULU_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "scenario_id": "<YOUR_SCENARIO_ID>",
    "avatar_id": "<YOUR_AVATAR_ID>",
    "runtime_vars": {
      "user_name": "Alex",
      "company_name": "Acme Corp",
      "support_ticket_id": "TICK-1024"
    }
  }'
```

## Error responses

Conversation connect, updates, detail, and recording errors return JSON with:

- `error` — human-readable message
- `error_code` — stable string you can switch on

HTTP status is still set, but several different failures share the same number (for example more than one kind of 403). Prefer `error_code`.

| `error_code` | Typical status | When |
| --- | --- | --- |
| `AUTH_MISSING` | 401 | No Bearer API key |
| `AUTH_INVALID` | 401 | API key not recognized |
| `AUTH_DENIED` | 403 | Key does not own this scenario |
| `VALIDATION` | 400 | Missing or invalid request fields |
| `SCENARIO_NOT_FOUND` | 404 | `scenario_id` does not exist |
| `AVATAR_NOT_FOUND` | 404 | `avatar_id` does not exist |
| `SESSION_NOT_FOUND` | 404 | Conversation session does not exist |
| `QUOTA_EXCEEDED` | 403 | No minutes (or call duration) remaining |
| `CONCURRENCY_LIMIT` | 403 | Too many concurrent calls for the plan |
| `RECORDING_NOT_STARTED` | 404 | Recording was not enabled for this session |
| `RECORDING_UNAVAILABLE` | 404 | Recording file is not available |
| `RECORDING_PROCESSING` | 409 | Recording is not ready yet |
| `INTERNAL` | 500 | Unexpected server error |

The React SDK copies `error_code` onto `error.code` when the session fails. Client-only codes such as `UPDATES_TIMEOUT` are not returned by the REST API.

## Getting Started

Use **Starting a conversation** for connecting and live status polling, then **Transcripts and recordings** for conversation analysis.

For talking-avatar video from a script, use **Clips** and **Takes**. The request-by-request flow is in [Workflow](/guides/clips/workflow).

You can also create and manage **scenarios** (including hosted links), **endpoints**, and **knowledge bases** with the same Bearer API key. Secrets used in endpoint headers are still created in the [dashboard](https://akapulu.com/secrets/).
